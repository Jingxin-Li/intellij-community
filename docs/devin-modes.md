# Devin 工作模式详解

本文档详细介绍了 Devin AI 助手的两种主要工作模式：Planning 模式和 Standard 模式。

## Planning 模式

Planning 模式是 Devin 在接收任务后的初始工作阶段，主要特点包括：

### 功能特点

- **信息收集**：Devin 会全面收集完成任务所需的所有信息，包括搜索和理解代码库，使用浏览器查找在线信息等。
- **代码分析**：通过 LSP（Language Server Protocol）命令深入分析代码结构，包括查找引用、定义和类型信息。
- **问题识别**：识别任务中的潜在问题和挑战，提前规划解决方案。
- **计划制定**：基于收集的信息制定详细的执行计划，确保任务能够高效完成。

### 工作流程

1. 接收用户任务后，Devin 首先进入 Planning 模式
2. 使用搜索命令和 LSP 命令探索代码库
3. 打开并分析相关文件，理解代码结构和逻辑
4. 收集足够信息后，调用 `suggest_plan` 命令提出执行计划
5. 与用户确认计划或根据用户反馈调整计划

### 使用场景

Planning 模式特别适用于：
- 复杂的代码修改任务
- 需要深入理解代码库的任务
- 需要制定详细执行步骤的项目

## Standard 模式

Standard 模式是 Devin 执行具体任务的工作阶段，在 Planning 模式完成后进入。

### 功能特点

- **计划执行**：根据之前制定的计划执行具体操作，包括修改代码、创建文件等。
- **实时反馈**：向用户展示当前和可能的下一步计划信息。
- **灵活调整**：能够根据执行过程中的新发现或用户反馈调整执行计划。
- **多任务处理**：可以接收用户的新指令、工作反馈、额外任务、GitHub评论或CI反馈。

### 工作流程

1. 从 Planning 模式转入 Standard 模式
2. 按照计划执行具体操作
3. 实时向用户提供进度更新
4. 处理执行过程中遇到的问题
5. 完成任务并向用户提供最终结果

### 使用场景

Standard 模式适用于：
- 执行已规划好的代码修改
- 创建或修改文件
- 运行测试和验证更改
- 提交代码和创建拉取请求

## 模式切换

Devin 在两种模式之间的切换是自动的：
- 当收集到足够信息并制定好计划后，从 Planning 模式切换到 Standard 模式
- 当用户提出新的任务需求时，可能会重新进入 Planning 模式

## 总结

Devin 的双模式工作方式确保了任务执行的高效性和准确性：
- Planning 模式专注于信息收集和计划制定
- Standard 模式专注于计划执行和任务完成

这种工作模式使 Devin 能够处理从简单到复杂的各种软件开发任务，提供高质量的开发辅助服务。
